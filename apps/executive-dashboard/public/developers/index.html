Developer documentation

NEXUS API

Keep your DMS and your CRM. NEXUS sits on top: it catches every enquiry, scores it, answers it on the dealership's own number, and hands the result back to the systems you already run.

The API gives your developers, your integrator, or a no-code tool the same data the NEXUS dashboard shows. Push leads and stock in, pull scored leads and appointments out, and subscribe to webhooks so your systems hear about a new or updated lead the moment NEXUS does.

REST + JSONPlain HTTPS requests, JSON bodies, one API key per integration.
Scoped to one dealershipEvery key belongs to one dealership. It can never read or write another's data.
Signed webhooksHMAC-SHA256 signatures on every delivery, with automatic retries.

Authentication

Create an API key in the NEXUS dashboard under Integrations → API keys. Keys start with nxk_live_ and are shown once, when you create them; store them in your secret manager, never in a browser or mobile app. Revoke a key from the same screen at any time.

Send the key as a bearer token on every request:

Authorization: Bearer nxk_live_XXXXXXXXXXXXXXXXXXXXXXXX

Use one key per integration (your DMS sync, your call system, your Zapier account) so you can revoke one without breaking the others.

Each key carries scopes chosen when it is created: leads:read, leads:write, inventory:read, inventory:write, calls:write, appointments:read. A request outside its key's scopes gets 403 insufficient_scope.

Base URL

https://dsvuoovivysszdoiorch.supabase.co/functions/v1/api-v1/v1

All paths below are relative to this base. Requests and responses are UTF-8 JSON; send Content-Type: application/json on requests with a body. Timestamps are ISO 8601 in UTC. Amounts are AED.

Endpoints

List endpoints return { "data": [...], "next_cursor": ... }, oldest change first; pass next_cursor back as cursor to get the next page. It is null on the last page and is opaque. Unknown query parameters are refused with 422 unknown_parameter. Single records come back as { "data": {...} }. Lead ids are integers.

POST

/leads

Scope leads:write. The lead enters NEXUS with source api and is scored and routed like any other lead. name and one of phone (E.164; UAE national numbers accepted) or email are required. Optional: vehicle_interest, budget_aed, notes (≤2000), source_detail (free text naming your system or form), occurred_at, external_id. Send your system's id as external_id or the Idempotency-Key header (not two different values): repeating the request returns the same lead with 200. A lead with the same email at your dealership is returned with duplicate_of: "email" and nothing new is created.

  -H "Authorization: Bearer $NEXUS_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: CRM-88412" \

    "phone": "+971501234567",
    "email": "omar@example.com",

Webhooks

Add an endpoint under Integrations → Webhooks: an https URL, the events you want, and NEXUS shows you a signing secret. When a subscribed event happens, NEXUS sends a POST to your URL within about a minute. Respond with any 2xx status within 10 seconds; do slow work after you respond.

EventWhen
lead.createdA new lead arrived from any source (website, WhatsApp, Meta, the API, a call).
lead.updatedA lead's status, owner or details changed.
lead.scoredNEXUS finished scoring a lead (ai_score is set).
appointment.createdA test drive or visit was booked.
appointment.updatedAn appointment was confirmed, moved, cancelled or completed.
message.receivedA customer sent a message on a connected channel.
pingSent when you press Send test on the Webhooks screen.

id is the same on every retry of one delivery, so store it and ignore repeats. Deliveries can arrive out of order; use created_at or re-read the lead with GET /leads/{id} when order matters.

NEXUS only delivers to public https URLs. http, localhost, private and link-local addresses are refused, and redirects are not followed — point the webhook at the final URL.

Verifying signatures

X-Nexus-Signature is t=<unix seconds>,v1=<hex>, where v1 is HMAC-SHA256 of t + "." + raw request body, keyed with your endpoint's signing secret. Verify against the raw bytes you received, before parsing JSON; compare in constant time; reject timestamps older than 5 minutes.

Node.js (Express)

const crypto = require('crypto');
const express = require('express');
const app = express();

function verifyNexus(secret, rawBody, header, toleranceSec = 300) {
  const parts = Object.fromEntries(header.split(',').map(p => p.split('=')));
  const t = Number(parts.t);
  if (!t || !parts.v1 || Math.abs(Date.now() / 1000 - t) > toleranceSec) return false;
  const expected = crypto.createHmac('sha256', secret).update(`${parts.t}.${rawBody}`).digest('hex');
  const a = Buffer.from(expected), b = Buffer.from(parts.v1);
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

app.post('/nexus-webhook', express.raw({ type: 'application/json' }), (req, res) => {
  const ok = verifyNexus(process.env.NEXUS_WEBHOOK_SECRET, req.body.toString('utf8'),
                         req.get('X-Nexus-Signature') || '');
  if (!ok) return res.status(400).send('bad signature');
  const event = JSON.parse(req.body);
  res.sendStatus(200);          // respond first
  handle(event);                // then do the work
});

Python (Flask)

import hmac, hashlib, os, time
from flask import Flask, request, abort

app = Flask(__name__)

def verify_nexus(secret: str, raw_body: bytes, header: str, tolerance: int = 300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(",") if "=" in p)
    t, v1 = parts.get("t"), parts.get("v1")
    if not t or not v1 or abs(time.time() - int(t)) > tolerance:
        return False
    expected = hmac.new(secret.encode(), f"{t}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, v1)

@app.post("/nexus-webhook")

                        request.headers.get("X-Nexus-Signature", "")):
        abort(400)
    event = request.get_json()
    # queue event["type"], event["data"] for processing
    return "", 200

PHP

<?php
function verify_nexus(string $secret, string $rawBody, string $header, int $tolerance = 300): bool {
    $parts = [];
    foreach (explode(',', $header) as $p) {
        [$k, $v] = array_pad(explode('=', $p, 2), 2, '');
        $parts[trim($k)] = trim($v);
    }
    if (empty($parts['t']) || empty($parts['v1']) || abs(time() - (int)$parts['t']) > $tolerance) {
        return false;
    }
    $expected = hash_hmac('sha256', $parts['t'] . '.' . $rawBody, $secret);
    return hash_equals($expected, $parts['v1']);
}

$raw = file_get_contents('php://input');
if (!verify_nexus(getenv('NEXUS_WEBHOOK_SECRET'), $raw, $_SERVER['HTTP_X_NEXUS_SIGNATURE'] ?? '')) {
    http_response_code(400);
    exit;
}
$event = json_decode($raw, true);
http_response_code(200);

Retries & backoff

A delivery counts as failed when your endpoint returns anything other than 2xx (including a redirect, which is never followed), takes longer than 10 seconds, or cannot be reached. The queue is drained once a minute. After a failed attempt the next one is scheduled after:

After failed attempt12345678
Next attempt in1 min5 min30 min2 h6 h12 h24 h— marked dead

So a delivery is attempted at most 8 times over roughly 45 hours. Delivery statuses are pending, delivered, failed (will be retried) and dead; the Webhooks screen shows each delivery's status, attempts and last HTTP code.

After 20 consecutive failed deliveries the webhook's status becomes disabled and its outstanding deliveries are marked dead. Fix your endpoint, delete the disabled webhook, add it again, and press Send test.

Because a retry repeats the same id, make your handler idempotent: if you have already processed that id, return 200 and do nothing.

Rate limits

Each API key may make 120 requests per minute. Over the limit you get 429 with a Retry-After header (seconds). Back off and retry after that many seconds. Use POST /inventory batches rather than one request per vehicle.

Errors

Every error has the same shape:

Recipes

Call system — 3CX, Aircall, Twilio → POST /calls

Every call your showroom takes becomes part of the lead's history, and a missed call from an unknown number becomes a lead instead of a lost customer.

  1. In your call system, add a "call ended" webhook (Aircall: call.ended; Twilio: the StatusCallback of the call; 3CX: a CRM integration template or call-report webhook).
  2. Point it at a small relay (or a Zapier/Make step) that maps the fields and calls POST /calls with your key. Keep the NEXUS key in the relay, not in the call system.
  3. Map: the call id → external_call_id, inbound/outbound → direction, caller number → from_number, your DID → to_number, start time → started_at, duration in seconds → duration_sec, recording link → recording_url.
// Aircall "call.ended" → NEXUS (Node relay)
const c = req.body.data;
await fetch(`${NEXUS}/calls`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${process.env.NEXUS_API_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({
    external_call_id: `aircall-${c.id}`,
    direction: c.direction,                    // "inbound" | "outbound"
    from_number: c.direction === 'inbound' ? c.raw_digits : c.number?.digits,
    to_number:   c.direction === 'inbound' ? c.number?.digits : c.raw_digits,
    started_at: new Date(c.started_at * 1000).toISOString(),
    duration_sec: c.duration,
    recording_url: c.recording || undefined,
  }),
});

DMS inventory sync — POST /inventory batch

Keep your DMS as the system of record for stock. Export the current stock list on a schedule (every 15–60 minutes) and send it in batches of up to 500. Each vehicle is keyed on stock_number or vin: unknown vehicles are created (send model), known ones are updated, sold cars are sent with your sold status, e.g. "status": "Sold".

# nightly or every 30 min from cron
jq -c '[.[] | {stock_number, vin, model, status, price_aed, cost_aed, acquired_at}]' dms_export.json |
curl -X POST "$NEXUS/inventory" \
  -H "Authorization: Bearer $NEXUS_API_KEY" -H "Content-Type: application/json" --data-binary @-

Check failed in the response and log the results entries that are not created/updated.

CRM two-way — Salesforce, HubSpot, Zoho, Bitrix24

  1. NEXUS → CRM: subscribe to lead.created (and lead.scored if you want the score). On each delivery, verify the signature, then create the lead in your CRM and store the NEXUS id on the CRM record.
  2. CRM → NEXUS: when a salesperson changes the stage in your CRM, call PATCH /leads/{id} with the new status, so the NEXUS dashboard and follow-ups stay truthful.
  3. Leads that start in the CRM: send them with POST /leads and your CRM id as external_id, so a retry never makes a duplicate.
// on lead.created
const lead = event.data;                     // the lead object itself
const crmId = await crm.createLead({ name: lead.name, phone: lead.phone, email: lead.email,
                                      note: lead.vehicle_interest, nexus_id: lead.id });

// later, when the CRM stage changes
await fetch(`${NEXUS}/leads/${nexusId}`, {
  method: 'PATCH',
  headers: { Authorization: `Bearer ${process.env.NEXUS_API_KEY}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ status: 'WON' }),
});

Zapier and Make — no code

Zapier: to react to NEXUS, create a Zap with trigger Webhooks by Zapier → Catch Raw Hook, copy its URL into Integrations → Webhooks in NEXUS, and press Send test. (Use Catch Raw Hook if you want to verify the signature in a Code step; Catch Hook is fine if you do not.) To send data to NEXUS, add the action Webhooks by Zapier → Custom Request: method POST, URL …/v1/leads, header Authorization: Bearer nxk_live_…, data as JSON.

Make: to react to NEXUS, start a scenario with Webhooks → Custom webhook and paste its address into NEXUS. To send data, use the HTTP → Make a request module: method POST/PATCH, body type Raw, content type JSON (application/json), and an Authorization header with your key. Turn on Parse response to use the returned data.id in later modules.
