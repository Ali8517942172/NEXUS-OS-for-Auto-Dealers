## A. `ops/tenant-isolation-tests/two-tenant-suite.sql` — unblocked

**Before:** `node ops/ci/no-destructive-scripts.mjs` → **exit 1**, 11 blocking
findings, all in this one file (8 × R1 schema teardown, 3 × R2 unpredicated
row removal).

**After:** `node ops/ci/no-destructive-scripts.mjs` → **exit 0**, prints `clean`.

**What changed, and why this way.**

The guard offers exactly two waiver mechanisms, and its own comments say what
each is for:

* `EXEMPT_DIRS` — three directories of *frozen historical evidence* that "record
  what was once true and must not be rewritten" (`ops/journey-lab/DO-NOT-RUN-IN-PRODUCTION/`,
  `ops/evidence/`, `AGENTS/`).
* `EXEMPT_LINES` — narrow waivers "PINNED TO A LINE NUMBER: if the file changes
  and the statement moves, the guard fires again and a human must look at it.
  Nothing here is a blanket file or directory pass."

The two-tenant suite is **not** frozen evidence. It is a live harness that will
be edited and re-run, so a directory pass would be the wrong mechanism and would
also silently cover anything else later dropped into that folder. The line pin is
the mechanism the guard was designed for, so that is what was used. No new
mechanism was invented and no silent bypass was added.

Two files were edited:

1. `ops/tenant-isolation-tests/two-tenant-suite.sql` — a 26-line block added to
   the existing header, headed *WHY THIS FILE IS DESTRUCTIVE ON PURPOSE*. It says
   in plain words that Part 1 tears down the schema and Part 4 fires unscoped
   removals deliberately; that the Part 4 probes roll back but the Part 1 teardown
   does not and is not reversible; that pointed at production this destroys the
   live Tenant A data with no undo and no backup taken by the script; that it is
   for staging `wwspuxrbiyagnrnzgate` and nothing else; and that the CI waiver is
   line-pinned, so moving these statements is *supposed* to re-fire the guard.
2. `ops/ci/no-destructive-scripts.mjs` — one `EXEMPT_LINES` entry pinning
   lines `76, 79, 80, 82, 83, 84, 85, 88, 1023, 1027, 1030`, with a comment
   giving the reason, the staging target, and the gap.

**Stated gaps, not hidden.**

* A pin catches *movement*, not *substitution*. If a genuinely destructive
  statement ever lands on one of those eleven line numbers it is waived silently.
  This is the same known gap the guard already documents for its QUALITY_GATE pin.
* Eleven pins is now the largest single waiver in the map. The comment says so:
  if it grows again, the signal is to build a real staging-only mechanism, not to
  keep adding line numbers.
* Line numbers are correct **as of this edit**. The header insert moved every
  statement down 26 lines; any further edit to the .sql re-fires CI by design.

## C. Billing, subscriptions, plans, trials, entitlements — the commercial truth

**There is none. Not an empty one — none at all.**

Evidence, production `dsvuoovivysszdoiorch`, read-only:

* `information_schema.tables` matched against
  `bill|subscrip|plan|trial|entitle|seat|invoic|price|pricing|tier|quota|licen|charge|payment|stripe`
  across every application schema: **zero table-name matches.**
* The same pattern against `information_schema.columns` returns 47 columns, and
  every one of them is about a *car*, not about a customer of ours:
  `inventory.price_aed`, `competitors.price_aed`, the `finance_quotes.*_payment_*`
  columns (auto-loan quotes offered to a car buyer), `deal_rescue_evidence_sources.evidence_tier`,
  and the `whatsapp_*` `pricing_*` / `billing_fact_state` / `provider_billable`
  columns — which record **what Meta charges us to send a message**, i.e. our cost
  of goods, not anyone's subscription.
* `pg_proc` in `public` matching the same pattern: **zero functions.**
* No enum type or label for a plan, tier, or trial state.
* `public.tenants` has seven columns in total — `id, name, slug, status,
  created_at, is_quarantine, is_unattributed_default`. There is no plan column,
  no trial-end date, no seat count, no entitlement flag. `status` carries exactly
  two values in production today: one `active` tenant and one `quarantine` tenant.
  It is an operational switch, not a commercial one.
* Repo grep corroborates rather than contradicts: the only `stripe` hits are a CSS
  comment about visual stripes and an n8n MCP-registry row inside the ignored
  `n8n_backup_utf8.sql`; the only `subscription` hits outside build output are
  n8n's own `agent_chat_subscriptions` internal table, and
  `apps/executive-dashboard/lib/setup.js`, which already tells the operator on
  screen that "there is no billing table, no subscription table and no trial
  table in this database."

So: a dealership can be created, scoped, and served today, and its usage cost to
us is measured — but **nothing in this system can charge anyone, hold a plan,
start or end a trial, count a seat, or gate a feature on entitlement.** Selling a
subscription today means invoicing and enforcing it entirely outside NEXUS.

*Implemented ≠ tested ≠ production-proven, and here it is not even implemented.*
This section establishes the fact only; it proposes nothing.
