## What changed in the gate

### 1 · L3 tested that the word was present, not that the option was true

`views_no_invoker` excluded a view when its `reloptions` string merely
**contained** `security_invoker`. A view created `with (security_invoker =
false)` contains that substring, so L3 passed it — while behaving in exactly the
way L3 exists to forbid. Proved on production, not argued:
`select 'security_invoker=false' ilike '%security_invoker%'` → **true**.

The test now parses the option's value and compares it against the spellings
Postgres accepts for true (`true/on/1/yes`, case-insensitively), because
Postgres stores what was written and does not normalise it. A naive `= 'true'`
would have been the same defect facing the other way.

**Measured after the fix, both projects:**

| | views in `public` | option present | option **true** | fail the new test |
|---|---|---|---|---|
| production `dsvuoovivysszdoiorch` | 39 | 39 | **39** | 0 |
| staging `wwspuxrbiyagnrnzgate` | 39 | 39 | **39** | 0 |

Production stores `security_invoker=true` on 38 views and
`security_invoker=on` on `v_competitor_latest`; staging holds both spellings
too. Both are true, and both now pass.

A catalogue dumped before this change carries a list built by the old test and
is indistinguishable from one built by the new one, so the catalogue now carries
a marker (`views_invoker_test`) and **L3 reports NOT RUN rather than PASS when
the marker is absent**.

The snapshot now records `takenAt 2026-09-05T20:56:16Z`, 98 relations

### 3 · Nothing watched the baseline — L12

New numbered check, `L12` (P1, same reasoning as L11, and stated in its header).
`L11`'s only opinion about `supabase/baseline/` was `hasBaseline` — a file
listing. L12 compares content:

- **A (offline, always runs)** — the restore path as falsifiable sentences:
  every stamped version has a file, every file at or below the baseline version
  is stamped, no stamped version is above it, names agree. Plus an HTML-entity
  sweep over the seed's **data** (comment lines excluded — that file's header
  describes the 4 September corruption *in entities*, and a naive sweep would
  report the repair note as the defect).
- **B (needs `NEXUS_DB_URL`)** — the vocabulary seed compared with the live rows
  **by value**: per table, a digest over the file's own row values against the
  same digest computed by Postgres. Row counts are reported and are explicitly
  not the test.
- **C (needs `NEXUS_DB_URL`)** — `supabase/tools/generate-baseline.mjs` re-run
  against the database with the version, name and date taken from the committed
  file, compared byte for byte.
- **C′ (needs `NEXUS_BASELINE_REPLAY_URL`)** — the folder's own claim, executed:
  `supabase/tools/verification-harness.sql`, the baseline, the history stamp and
  the seed replayed into an **empty** PostgreSQL 17, then the generator run
  against the replica. It refuses a target that is not empty, and refuses one
  that is the audited database by connection string *or* by database
  fingerprint.

If no arm compared anything with a database, L12 is NOT RUN. If some arms ran
and others did not, L12 verdicts on what ran and `L12b` puts the unrun arms on
the board rather than in a footnote.

**Arm B was validated out of band, because its own lane is NOT RUN here.** The
digest recipe was run against production through the MCP: all 19 tables, 190
rows, **every digest equal to the file's**. And against a copy of the seed with
`->` re-escaped to `-&gt;`: **every row count identical, three table digests
different** (`attribution_link_basis`, `attribution_edge_type`,
`attribution_event_type`). That is the defect that survived the first
verification pass, caught.

### 4 · Other presence-vs-effect defects found in the hunt

**Fixed, and each one measured before and after:**

- **L5 asked whether a grant was written, not whether `anon` can execute.** Its
  filter was `/anon=X/` on `proacl`. `anon` also inherits every PUBLIC grant
  (grantee empty, `=X/postgres`) and can hold EXECUTE through role membership,
  and neither matches. Measured on production: the regex found **0** functions,
  `has_function_privilege('anon', …, 'EXECUTE')` found **1** —
  `nexus_public_exposure_report`, held through `=X/postgres`. The catalogue now
  carries `exec_anon`/`exec_auth` and L4 and L5 read those, falling back to the
  regex (widened to include PUBLIC, i.e. the stricter reading) only for an older
  catalogue. L5 still passes — that function is SECURITY INVOKER and its body
  reads no tenant-owned table — but its evidence line used to say "the grant is
  absent everywhere", which was false.
- **L2 read `relacl` and could not see a column-level grant.** CLAUDE.md records
  this for `policy_platform_attestation`; it is live on `workflow_registry`,
  whose `relacl` names only `postgres` and `service_role` while seven of its
  columns carry `authenticated=r`. The exemption conjunction now measures what
  the roles may actually do (`has_table_privilege` +
  `has_any_column_privilege`, for `authenticated` **and** `anon`), unioned with
  the ACL letters so the fallback can only add. No verdict changed today — every
  exempt table measures `SELECT` only — which is the point: the check is right
  now, before it matters.
- **L2 arm 1 could not see a partitioned table.** `tables_no_rls` filtered
  `relkind='r'`; a partitioned parent with RLS off was invisible. Now `('r','p')`.
  There are none on either project today, which is why it cost nothing to fix.
- **L3 was structurally blind to a materialized view.** A matview reads its base
  tables as its owner, no policy applies, and it carries no `security_invoker`
  option — the L3 exposure with the mechanism removed rather than mis-set. The
  catalogue now reports `rls_incapable_relations` and `L3b` WARNs on it. Empty
  on both projects today.
- **L10's evidence asserted a constraint it had never read.** It counted rows
  and then said "the CHECK `inventory_actions_recovered_needs_real_sale` holds".
  Zero bad rows is exactly what a table with that constraint dropped this
  morning looks like. The constraint is now selected in the same catalogue, L10
  prints its definition, and `L10b` WARNs if the rows are clean and the
  constraint is gone. It is present on production and printed in the run above.
- **R7 accepted any disabled button as proof the decision controls were
  refused.** `button[disabled]` counts a button some other handler disabled
  mid-save. It now counts `button[data-decide]` and requires every one of them
  to be disabled on a session the database says may not decide — and it checks
  for the **exact refusal sentence the stub served**, declared once and shared,
  rather than for `/not an approver|may not decide|account owner|manager/i`,
  which any list of staff job titles would satisfy. Result this run: 9 decision
  controls rendered, 9 disabled, sentence present (10 disabled buttons on the
  screen in total, reported as context and deliberately not the test).

**Found and NOT fixed — listed because I am not confident a fix would be right,
and each one is a P0 resting on a token rather than on an effect:**

1. **L4's tenant predicate is a substring search.** For each write statement it
   reads 900 characters and passes if `tenant_id` appears anywhere in that
   window. A function whose `UPDATE` carries no tenant predicate but names
   `tenant_id` in a nearby column list, a comment-free string, or the *next*
   statement, passes. The honest fix is either to parse the statement or to
   prove the scoping by probing as a second tenant (which is B3's shape, and
   which needs a database). Tightening the regex naively would cry wolf on
   correct code, which is how a gate stops being read.
2. **L5's "reads tenant-owned data" is likewise textual** — a regex over the
   function body against a hand-written table list. A read reached through a
   view, or a dynamic `EXECUTE format(...)`, is invisible to it.
3. **L2 arm 2 detects an open policy by the literal string `true`.**
   `pg_policies.qual = 'true'`. A policy written `USING (1=1)`, `USING (true is
   true)` or any other predicate that admits every row is exactly as open and is
   not in the list. The real witness is a read as the role, which the B lane can
   do and the catalogue cannot.
4. **S8's second arm tests that the string `calculation_id` appears somewhere in
   the file**, not that the instalment rendered is gated on it. Any unrelated
   query that selects the column satisfies it.
5. **S10 requires `lib/health.js` to be *imported*,** not that the audit status
   is classified through it. Its first arm (no self-classification) carries most
   of the weight.
6. **S4's browser-tenant-scoping test is a 400-character proximity window**
   between `dbWrite(` and `tenant_id:`. A write that composes one further away
   is missed.
7. **R4 accepts the words "not computable / unknown / insufficient" anywhere on
   the Inventory screen**, not beside the figure that is missing.
8. **The catalogue's 24-hour freshness tolerance is a fuse, not a lock** —
   already recorded in CLAUDE.md. A catalogue 23.9 hours old is accepted and
   produces a full live verdict.

Items 1–3 are the ones worth a pass of their own: they are P0s whose evidence is
a token, and the honest witness for all three is a probe as a real role rather
than a smarter regex.
